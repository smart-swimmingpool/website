## How to Contribute

### Reporting Issues

- **Check existing issues**: Search
  [GitHub Issues](https://github.com/smart-swimmingpool/website/issues)
  before creating a new one
- **Include**:
  - Page URL with the issue
  - Screenshot (if visual issue)
  - Browser and OS information
  - Steps to reproduce

### Suggesting Enhancements

- **Check the roadmap**: See [README.md](README.md) for planned features
- **Discuss first**: Open a
  [GitHub Discussion](https://github.com/smart-swimmingpool/smart-swimmingpool.github.io/discussions)
  to discuss your idea
- **Check for duplicates**: Search existing issues and PRs

### Submitting Pull Requests

- **Fork the repository**: Create your own fork
- **Create a feature branch**: Use descriptive branch names
  (e.g., `feat/add-pool-controller-guide`, `docs/update-getting-started`)
- **Test your changes**: Verify links and content
- **Update documentation**: Keep docs in sync with changes

## Getting Started

### Prerequisites

- [Hugo Extended](https://gohugo.io/installation/) v0.162.1 or later
- [Python](https://www.python.org/) 3.x
- [Git](https://git-scm.com/) with submodule support
- [Node.js](https://nodejs.org/) (optional, for some build tools)

### Setting Up the Development Environment

```bash
# Clone the repository with submodules (for the theme)
git clone --recursive https://github.com/smart-swimmingpool/website.git
cd website

# Create a Python virtual environment (optional but recommended)
python3 -m venv .venv
source .venv/bin/activate   # On Windows: .venv\Scripts\activate

# Install Python dependencies
pip install -r requirements.txt

# Start the Hugo development server with live reload
hugo server -D
```

The site will be available at `http://localhost:1313`. Changes to content, layouts, and config are reflected immediately.

## Content Guidelines

### Markdown Formatting

- **Line Length**: Wrap lines at ~80 characters for readability
- **Headings**: Use semantic heading hierarchy (h1 > h2 > h3)
- **Images**: Place in `static/img/` and reference with `/img/...`
- **Links**: Use descriptive link text, not "click here"
- **Code Blocks**: Use triple backticks with language specification

### Front Matter

All content files should include YAML front matter:

```yaml
---
title: "Page Title"
date: 2024-01-01
description: "Page description for SEO and social sharing"
tags: [tag1, tag2]
---
```

### Translations

- **German pages**: Use `*.de.md` filename suffix
- **Structure**: German pages should mirror English version's structure
- **Consistency**: Update both English and German versions when making changes

### Images

- **Location**: Place in `static/img/`
- **Optimization**: Optimize images before committing
- **References**: Use `/img/filename.ext` in Markdown

## Pull Request Process

1. **Fork the repository** and create your branch from `main`
2. **Make your changes** following the guidelines above
3. **Test locally**: Run `hugo server -D` and verify your changes
4. **Check links**: Run `make check` or use the CI workflow
5. **Update documentation** if applicable
6. **Commit your changes** with clear, descriptive messages
7. **Push to your fork** and submit a pull request

### Pull Request Requirements

- ✅ All CI checks pass (build, link check)
- ✅ Content follows project standards
- ✅ Documentation is updated
- ✅ No broken links
- ✅ Clear commit messages

## Commit Message Guidelines

### Format

```text
type(scope): subject

body

footer
```

### Types

- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Formatting changes (no functional changes)
- `refactor`: Code refactoring
- `chore`: Maintenance tasks
- `i18n`: Translation updates

### Example

```text
docs(pool-controller): add troubleshooting guide

- Add comprehensive troubleshooting guide for pool controller
- Include common issues and solutions
- Add screenshots for error messages

Closes #123
```

## Quality Gates

All contributions must pass the following quality checks:

1. **Build**: Hugo site builds successfully
2. **Link Check**: No broken links (using lychee)
3. **Manual Review**: Content review by maintainers

### Local Quality Checks

```bash
# Build the site
hugo --minify

# Start development server
hugo server -D

# Check for broken links (requires running server)
# Then access http://localhost:1313 in browser
```

## Module Documentation Updates

The website automatically pulls documentation from module repositories using `grabrepos.py`.

### How It Works

1. **Reads `multiversion.yml`** to find which repos to include
2. **Clones repos** into `temp/` directory
3. **Extracts and processes** Markdown files
4. **Writes to `content/docs/{modulename}/`**

### For Module Maintainers

To trigger a website rebuild when your module docs change, add this workflow to your repo:

```yaml
# .github/workflows/trigger-website-rebuild.yml
name: Trigger Website Rebuild
on:
  push:
    branches: [main]
    paths: ["docs/**"]
jobs:
  trigger:
    runs-on: ubuntu-latest
    steps:
      - name: Repository Dispatch
        uses: peter-evans/repository-dispatch@v3
        with:
          token: ${{ secrets.WEBSITE_DISPATCH_TOKEN }}
          repository: smart-swimmingpool/website
          event-type: doc_update
```

See [docs/trigger-website-rebuild.md](docs/trigger-website-rebuild.md) for detailed instructions.
